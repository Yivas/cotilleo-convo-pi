# Contributing

Documentation corrections, design proposals, issues and pull requests are accepted. This is pre-development: there is no plugin, supported release, package manager or build/test command to run. A missing planned capability is not a regression in an implemented feature.

## Issues

The [issue chooser](https://github.com/Yivas/cotilleo-convo-pi/issues/new/choose) offers a problem report and a proposal form. Existing [issues](https://github.com/Yivas/cotilleo-convo-pi/issues) should be checked first. A problem report should identify the document or commit, host and OS if relevant, reproduction, expected behavior and observed behavior. A proposal should describe the user task, boundaries and how success could be verified.

Security-sensitive reports use [SECURITY](SECURITY.md), not public issues. Credentials, tokens, private prompts, conversations, personal paths, model configuration and logs containing private data must not be attached.

## Pull requests

A [pull request](https://github.com/Yivas/cotilleo-convo-pi/pulls) should keep one coherent change and explain motivation, verification actually performed, compatibility implications, risks and documentation changes. New product behavior needs agreement on its contracts before implementation; a proposal or PR does not itself authorize installation, deployment or access to external resources.

For documentation changes, reading the rendered text and checking affected links is enough unless the change requires more. No fictitious test commands or tests for the presence of strings are expected. The PR should distinguish checks run from checks not applicable or not run. Submission does not guarantee acceptance or a review date.
